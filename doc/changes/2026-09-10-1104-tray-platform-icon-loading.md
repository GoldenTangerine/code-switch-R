# 托盘平台图标加载修复

- 变更时间：2026-09-10 11:04:17（Asia/Shanghai，UTC+08:00）。
- 评审修正时间：2026-09-10 11:30:00（Asia/Shanghai，UTC+08:00）。
- 涉及范围：`frontend/src/components/Tray/Index.vue`、`frontend/src/components/Tray/Index.icons.test.ts`。

## 原因与变更内容

托盘应用共享快照时仅预加载供应商图标，未加载平台标题图标。Claude 图标解析为需要异步加载的 `claude-color`，当供应商使用其他品牌图标时，该资源始终未加载，标题便显示备用文字 `claude`。Codex 在供应商同样使用 OpenAI 图标时会因共享图标缓存而正常显示。

将快照的平台图标与供应商图标一起加入预加载列表，复用图标别名解析和响应式缓存，使平台标题在资源加载完成后显示 SVG；平台没有供应商时同样生效。

评审发现供应商图标也存在异步加载问题：快照应用时保存了尚未加载的 SVG 空字符串，后续缓存更新不会触发该字符串重算。改为在模板渲染时通过供应商图标键读取响应式缓存，资源加载完成后立即更新，无需等待快照内容变化。

图标加载移至快照内容去重之前，单独捕获加载异常并记录警告。相同图标集合成功后不重复加载；失败后间隔 5 秒利用现有托盘轮询重试，加载期间不重复发起整组请求。窗口失焦、隐藏或卸载后由现有生命周期停止轮询，不新增重试定时器；已经发出的加载允许完成并更新共享缓存。

平台备用文字改为名称的大写首字母，并固定图标容器宽度、裁剪溢出，避免首次加载或加载失败时文字与标题重叠。沿用现有亮暗主题颜色和品牌资源。

组件回归测试覆盖 Claude 搭配智谱供应商、Gemini 无供应商时的真实 SVG 加载，以及失败冷却、快照不变时恢复、成功后不重复加载、请求未完成时去重、失焦后暂停、重新激活后重试和卸载后停止重试。

## 验证结果

- 修改前运行新增测试失败：预期两个平台 SVG，实际为零，复现缺陷。
- `cd frontend && pnpm test:unit src/components/Tray src/utils/providerIconAssets.test.ts`：9 个文件、60 项测试通过，其中图标组件回归测试 3 项。
- `cd frontend && pnpm exec vue-tsc --noEmit`：通过。
- 未构建或启动桌面应用；实际 Wails 托盘窗口的视觉验收尚未执行。

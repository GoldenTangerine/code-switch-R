# 技能库与应用开关

变更时间为 2026-11-20 15:50:00（Asia/Shanghai，UTC+08:00）。

评审修正时间为 2026-11-20 16:20:00（Asia/Shanghai，UTC+08:00）。

涉及范围包括 Skills 页面、Go 技能服务、Wails 绑定及中英文文案。

发布版本为 v2.12.3，同步各平台构建元数据和版本更新说明。

## 变更内容

- 「已安装」按技能列出 Claude Code、Codex、Gemini CLI、OpenCode、Grok Build、OpenClaw、Hermes 和 Pi 的用户级开关。主副本存放在 `~/.code-switch/skills`，优先用软链接同步到应用目录，软链接不可用时复制文件。关闭所有开关后仍可查看技能内容、重新启用或卸载。
- 「发现」保留自定义 GitHub 仓库，支持从仓库根目录及子目录发现技能，安装时可选择多个应用。已安装页直接读取本地文件，打开「发现」才请求仓库。
- 已有用户级技能可手动纳入管理。若对应应用目录里已有内容不同的同名技能，页面标记冲突并保留该目录。修改过的同步副本受到保护，卸载和停用时会提示先移出该目录。多应用操作失败时回滚本次文件变更。
- 项目级技能按当前工作目录展示。OpenCode、Pi 和 OpenClaw 新的项目级安装分别写入 `.opencode/skills`、`.pi/skills` 和工作区的 `skills/`。页面同时列出旧路径。Pi、OpenCode、OpenClaw 和 Hermes 可查看嵌套的技能目录。
- 开关管理各应用的用户级技能。OpenCode 和 Grok Build 可以按技能停用继承自其他目录的技能，页面显示继承来源、原生停用、断链与目录不可用等状态。应用自身的项目配置、插件及更高优先级的规则仍参与加载。
- 用真实路径识别共享目录，避免从本地技能列表删除管理库中的主副本。单个目录读取失败时，保留其他应用和技能的列表并展示报错详情。
- 主副本未登记时可直接纳入管理。缺失的主副本可以从内容未经修改的部署副本或原始仓库恢复。

## 验证结果

- `go test ./services/...` 覆盖多应用安装、同名冲突保护、失败回滚、归档路径校验、共享目录、部分失效、异常恢复及 OpenCode 和 Grok Build 的配置读写。
- `pnpm test:unit` 覆盖本地读取、应用开关、多应用安装、异常状态与恢复入口。
- `pnpm exec vue-tsc --noEmit` 通过。使用 Wails 3 CLI 验证绑定生成。
- 按项目约定未启动桌面应用，CLI 实际加载与桌面视觉效果未做手动验证。
